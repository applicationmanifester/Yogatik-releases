## New Module: electron/pagePipeline.cjs

The page itself becomes the AI's context. One module owns the whole pipeline; main.cjs gets a single delimited `[page-pipeline]` hook. Every model call routes through aiEngine's existing `chat()` path (aiEngine has no exported `ask()`; `chat()` with a system+user pair IS the one-shot ask the companion panel uses — no second LLM client was created).

1. **`getSelectionText(webContents)`** — selection grab via `executeJavaScript` over `window.getSelection()`, wrapped in try/catch. The clipboard fallback is guarded twice: it reads ONLY the X11 `'selection'` buffer (never the default clipboard, which would siphon whatever the user last copied for an unrelated app) and degrades to a clean `{ success:false }` when the clipboard bridge is unavailable. An empty selection is a result, not an error.
2. **`summarizePage(pageText, opts)`** — chunk-tolerant summarizer: truncates to a token-ish budget (default 3000 tokens ≈ 12 000 chars at ~4 chars/token) with an honest `[Page text truncated to N of M …]` marker, then routes through `aiEngine.chat` with the page-context system line `You are summarizing a web page; title: X; url: Y`. When no model is reachable (offline / `NO_MODEL`), a deterministic extractive summary answers under `via: 'Templates'` — the panel always answers, and so does the pipeline.
3. **`askAboutSelection(selection, pageText, opts)`** — composes the prompt with the quoted selection (`Selected text: "…"`), the question, and a ±600-char window of surrounding page context (falls back to the head of the page when the selection is not found verbatim). Same `aiEngine.chat` routing and same template fallback.
4. **`exportPageToPdf(webContents, { outPath })`** — `webContents.printToPDF({ printBackground: true, margins: { top/bottom/left/right: 0.4 } })`, saved with the settings-store's atomic-write discipline: temp file + `renameSync`, temp file unlinked on any failure, so a crash mid-write can never leave a truncated .pdf that looks like a real export. Refuses non-absolute destinations up front.
5. **`watchPage(monitor, opts)`** — subscribes to pageMonitor's change events (new `onPageChange` subscription; NO polling loop of its own). A change appends a capped watch-log entry (`getWatchLog()`) and shows a desktop `Notification` guarded by a permission check (`pageWatchNotifications` setting, default on, plus `Notification.isSupported()`); when gated off, the log entry still records the change.

## Wiring

6. **pageMonitor.cjs** — added the minimal change-event surface: `onPageChange(fn)` subscriber registry invoked from `notifyChange()`. When subscribers exist they own the desktop notification (with the permission gate) and the log; with none, the module's built-in unguarded notification fires exactly as before — behavior-preserving, no double notifications.
7. **browserWindowPreload.cjs** — new `__pagePipeline` bridge (`ask-yogatik-selection`, `export-page-pdf`, `get-selection`) behind a `PAGE_PIPELINE_ACTIONS` Set, same whitelist discipline as `DOWNLOAD_ACTIONS`/`VALID_ACTIONS`: non-whitelisted actions and non-object payloads are refused in the renderer before IPC is ever touched.
8. **main.cjs** — one delimited `[page-pipeline]` block in `whenReady()` calls `pagePipeline.wirePagePipeline({ ipcMain, app, getMainWindow, sessions, layout, syncTabBar })`, which registers the bounded `browser:page-pipeline` IPC handler, attaches the tab context menu to every page webContents (via `web-contents-created`, hostWebContents/type discriminated), and subscribes page-watch events. `layout`/`syncTabBar` added to the existing browserControl import; `syncTabBar` added to browserControl's module.exports (one word) so the pipeline can push companion-panel visibility instead of duplicating the nav-state push.
9. **Tab context menu** — on each page's `context-menu` event: "Ask Yogatik about selection" (enabled only when `selectionText` is non-empty), "Save page as PDF to Yogatik", and "Read this page" (readerMode narration chain when it ever exposes one; today just the reader overlay). "Ask" routes through the bounded dispatcher, which makes the companion panel visible (`aiPanelOpen` + `layout` + `syncTabBar`) and posts the answer on the same `__setAiResult` channel the panel already listens on.

## Security Posture

10. **Sender-bound IPC** — `browser:page-pipeline` verifies `chrome.webContents === event.sender` before any work; page webContents or any other surface gets `{ success:false, error:'forbidden sender' }`. The action whitelist is enforced on BOTH sides (preload Set and dispatcher Set). Raw page text never appears in a return value — only derived results (an answer, or the selection the chrome explicitly asked for). Payload fields are length-capped (question 2 000, selection 8 000, outPath 500 chars).

# [chromium-privacy] Chromium privacy & network stack — DoH/ECH, CSP injection, containers, storage audit

**Date:** October 18, 2026
**Scope:** yogatik-browser/ — network privacy layer (encrypted DNS, response-header hardening, cookie-jar containers, origin storage audit)
**Verification:** npm test → 78 passed, 0 failed (17 node --check + 5 settings-store + 27 page-pipeline + 29 chromium-privacy)

## New Module: electron/privacyStack.cjs

Four capabilities in one module so main.cjs keeps two delimited hooks total. Pure decision helpers (`buildDnsSwitches`, `decideCsp`, `withOptionalCsp`, `groupCookiesByDomain`, `containerPartition`) are exported and tested without touching Electron.

1. **`enableSecureDns(app, dnsSettings)`** — DNS-over-HTTPS via Chromium's DnsOverHttps feature plus Encrypted Client Hello (`EncryptedClientHello`), honoring settings `privacy.dns { mode: 'off'|'secure'|'auto', template }`. The pure spec builder `buildDnsSwitches()` maps: `off` → no switches; `secure` (default; missing/invalid modes fall back here) → `DnsOverHttps<DnsOverHttpsMode=secure` + ECH + templates; `auto` → DoH+ECH without a pinned mode. Default templates are Cloudflare + Google (RFC 8484); a user `template` string is honored verbatim. The switches are appended at main.cjs MODULE TOP-LEVEL — command-line switches only take effect before `app.ready`, which is exactly why this is not in `whenReady()` (the pre-existing DoH appends inside `applyNetworkPrivacy()` run after ready and were left untouched as not-this-track's code).
2. **`decideCsp(existingHeaders, host, enabled)`** — pure header decision: returns the policy string ONLY when the response carries no CSP header of its own (any casing, `-Report-Only` included), the host is a public http(s) target (file://, devtools://, yogatik://, chrome://, about:, data:, localhost, loopback and LAN ranges are always exempt), and the feature is enabled. `enabled` accepts the raw `privacy.cspInjection` settings block (`{ enabled: false, allowlist: [], policy: '' }` — OFF by default, allow-list gated with dot-boundary subdomain matching, optional policy override) or a bare `true` (wildcard, tests only). The default policy is conservative (`default-src 'self'; script-src 'self'; …; object-src 'none'; base-uri 'none'; frame-ancestors 'self'`).
3. **webRequest composition (the load-bearing discovery)** — Electron registers exactly ONE listener per webRequest event per session; a second `onHeadersReceived` would silently REPLACE main.cjs's `applyCSP` and drop the chrome/baseline security headers. So default-session CSP injection rides the existing `applyCSP` handler through a four-line `withOptionalCsp(url, headers, getSetting('privacy.cspInjection'))` hook (marked `[chromium-privacy]`), and `installCspInjection(session)` (the exported standalone wiring) is for container sessions, which have no other listener.
4. **Containers** — `containerPartition(id)` normalizes and maps ids to `persist:container-<id>` partitions (stable across restarts, unique, `../evil`/oversized/non-string ids → null). `createContainerSessions(map, opts)` builds one Electron session per valid id via injected `fromPartition`; distinct per-container user agents exist (`<baseUA> YogatikContainer/<id>`) but are OFF by default (`privacy.containers.distinctUserAgents`). `openInContainer(deps, containerId, url)` goes through browserControl's existing `createTab(s, url, { partition })` path (which natively supports partitions) and stamps `tab.containerId` so tree-node container assignment has a stable key — no browserControl.cjs edit was needed.
5. **Origin storage audit** — `groupCookiesByDomain(cookies)` is a pure merge-sort group-by (`.youtube.com`/`YOUTUBE.com` collapse, count desc); `auditOriginStorage(session)` adds the `session.getStorageData()` usage estimate WHEN the API exists (reported as null otherwise, a throwing one never fails the audit); `wipeOrigin(session, origin)` removes exactly the target origin's cookies — bidirectional dot-boundary matching so `.youtube.com` cookies wipe with `www.youtube.com` and vice versa, while `notyoutube.com` stays — then scopes `clearStorageData({ origins: [...] })` to the same origin.

## Wiring (all delimited `[chromium-privacy]`, additive only)

6. **main.cjs boot block** (top-level, before the window-state section) — requires privacyStack and calls `enableSecureDns(app, getSetting('privacy.dns'))` before ready. One block, removable without trace.
7. **main.cjs whenReady block** (after `[/lifecycle]`) — `wirePrivacyStack({ ipcMain, getSetting, setSetting, defaultSession, sessions, ensureSession, createTab, showActive, mainWindowGetter })` registers four IPC channels: `privacy:containers-list` / `-create` / `-open` (create normalizes + persists to `privacy.containers.list`, refuses duplicates and invalid ids; open resolves the chrome window's session, creates the tab inside the partition and stamps it), `privacy:storage-audit` (top-50 origins cap on the wire), `privacy:wipe-origin` (string origins only at the IPC boundary). Persisted containers are pre-warmed through `createContainerSessions` at wiring time.
8. **main.cjs applyCSP hook** — the four-line `withOptionalCsp` merge described in 3; the baseline `X-Content-Type-Options`/`Referrer-Policy` headers are unchanged.
9. **browserWindowPreload.cjs** — `__privacy` bridge (`containers.list/create/open`, `storageAudit`, `wipeOrigin`) behind string-typed args, main-side re-validation kept as the real gate (a renderer-side check alone is not a check).
10. **browserWindow.html** — minimal, additive: a `🧩` toolbar popover next to the new-tab button ("New tab in container" list + `+ New Container` prompt, plus a "Stored Data" section with the audit summary and per-origin Wipe buttons), wired in its own `<script>` block that no-ops unless `window.__privacy` exists. 11. **settings/defaults.json** — the `privacy` block gains `dns { mode: 'secure', template: '' }`, `cspInjection { enabled: false, allowlist: [], policy: '' }` (OFF by default), `containers { enabled: false, distinctUserAgents: false, list: [] }`. # [lifecycle] Tab lifecycle & performance — sleeping tabs, metrics HUD, crash resilience, spellcheck, power

**Date:** October 18, 2026
**Scope:** yogatik-browser/ — tab lifecycle & performance layer (Chromium tech: memory discarding, per-renderer metrics, renderer-crash recovery, spellcheck, powerSaveBlocker)
**Verification:** npm test → 105 passed, 0 failed (17 node --check + 5 settings-store + 27 page-pipeline + 29 chromium-privacy + 27 tab-lifecycle)

## New Module: electron/tabLifecycle.cjs

The tab model it manages is browserControl.cjs's session object ("tab tree"): `tree.tabs` Map of tabId → node (`view`, `webPrefs`, `pinned`, `savedUrl/savedTitle/savedScroll`, `hibernating`, `isAgent`), views parented through `tree.win.contentView` — insertion order of the Map IS the tab-strip order, which is what "same position" means for wake. Pure decision helpers (`pickSleepCandidates`, `mapMetricsToTabs`, `shouldAutoRestore`, `spellcheckLanguagesForLocale`, `hostIsBlocklisted`) are exported and tested without touching Electron.

1. **Sleeping tabs** — `registerTree(tree, { sleepAfterMs })` registers a session (settings `performance.sleepAfterMs` is the default budget, 20 minutes; `sleepAfterMs: 0` disables sleeping). A 30s sweeper enriches every node with live state (pinned, `webContents.isCurrentlyAudible()`, hasView, lifecycle state, last-active timestamp) and calls the pure `pickSleepCandidates(nodes, now, { activeId, sleepAfterMs, blocklist })`. Never sleeps: the ACTIVE tab, pinned tabs, audible tabs (destroying their renderer would kill playback), agent tabs (automation state cannot survive a reload), new-tab pages (nothing to preserve), viewless lazy tabs, and anything on the settings blocklist (exact host or subdomain of a listed host). `sleepTab` captures `{ id, url, title, scrollHint, position }` while the renderer can still answer (the scroll hint needs a live page, so it happens BEFORE destroy), then detaches the view from the surface's contentView and destroys the webContents — the same choreography browserControl's `hibernateTab` uses — keeping the NODE with state `tab.sleep = { state: 'asleep', ... }` and mirroring the capture into `savedUrl/savedTitle/savedScroll`, the fields `listTabs`/`navSnapshot`/session persistence already read for a down tab. Tabs the built-in timer hibernated directly are backfilled into the same state shape on the next sweep.
2. **Wake** — `wake(tree, tabId, { activate })` rebuilds the view at the SAME position (the node never left `tree.tabs`): an injectable view factory (`setViewFactory`) creates the WebContentsView with the tab's own `webPrefs`, AdShield is re-injected, the cleaned Chrome UA is re-set, and `wireTabListeners` (browserControl's, newly exported) re-wires full fidelity — console ring, ref epochs, network capture — so a woken tab is exactly as capable as a new one. The saved url is reloaded and the saved scroll is re-applied on `did-finish-load`; `activate` also makes the tab active.
3. **Per-tab metrics HUD** — `sampleMetrics()` maps `app.getAppMetrics()` onto tabs by renderer process id (`tab.view.webContents.getProcessId()`), exposed as a plain `{ [tabId]: { cpu, memoryKB } }` map (JSON-ready for a future IPC/HTML surface). The pure mapper `mapMetricsToTabs(metrics, [{tabId, pid}])` is separately exported and tested. A 10s sampler (`startMetricsSampler`/`stopMetricsSampler`, one timer only, `latestMetrics()` for the last pull) runs from `init`.
4. **Crash resilience** — `render-process-gone` no longer deletes the tab. browserControl's handler keeps its detach-view step but delegates to a `setCrashHandler` hook; `tabLifecycle.handleCrash` marks the node `crashed` with the Electron `detail.reason` (`clean-exit` — e.g. a renderer we destroyed ourselves — is ignored), then applies the policy: auto-restore through the SAME wake path exactly ONCE and only for `crashed`/`oom` reasons (`shouldAutoRestore(autoRestores, { maxAutoRestores: 1 })`); a `killed` renderer never auto-restores; after the budget is spent the tab stays crashed until a user action calls `wake`. No reload loops, ever. `autoRestores` persists across later sleep/wake cycles via the sleep-record spread.
5. **Spellcheck** — `applySpellcheckSettings()` honors `performance.spellcheck` (default true): `session.setSpellCheckerEnabled(true)` on the default session plus `setSpellCheckerLanguages(spellcheckLanguagesForLocale(app.getLocale()))` — bare locales ('en', 'fr') get their default region appended ('en-US', 'fr-FR') because Electron wants full BCP-47 tags; `disableSpellcheck()` is the exposed off-path.
6. **Power** — ONE `powerSaveBlocker` (`'prevent-display-sleep'`) is held only while a registered tree's ACTIVE tab is playing media — tracked via the tab's own `media-started-playing`/`media-paused` events (lazy-wired on first sweep sighting) with an `isCurrentlyAudible()` fallback for audio-only players — and released on tab switch, sleep, crash and teardown. Wrong in either direction looks bad, so the hold is strictly "playing right now": a paused video releases it, and a switch away releases it.

## Wiring (additive seams, each marked `[lifecycle]` in place)

7. **browserControl.cjs — `hibernateTab` guards** — the built-in 5-minute fixed timer previously destroyed ANY background tab's renderer, including an AUDIBLE one (killing its playback) and pinned/agent tabs. It now refuses `pinned || isAgent` and audible tabs, matching the lifecycle's own guard list, so both destructive paths agree.
8. **browserControl.cjs — `setTabBarSyncHook`** — every tab mutation funnels through `showActive → syncTabBar`; the lifecycle registers one observer hook there (auto-registers late-created sessions, timestamps active-tab activity, refreshes power state) instead of touching each mutation site. `wireTabListeners` (re-wiring for woken views) and `setCrashHandler` are exported alongside; the `[page-pipeline]` track's `syncTabBar` export line is untouched.
9. **main.cjs — ONE delimited `[lifecycle]` block** in `whenReady()` (between `[/page-pipeline]` and the `[chromium-privacy]` session block): `lifecycle.init({ sessions })` + `app.on('will-quit', stopAll)`. Entirely additive — removing the block returns the browser to plain open/activate/close behavior.
10. **settings/defaults.json** — new `performance` block: `sleepAfterMs: 1200000` (20 min), `blocklist: []`, `spellcheck: true`. No store.cjs change was needed: DEFAULTS already come from defaults.json through the existing `structuredClone`/atomic-write/reset discipline (regression-guarded by suite 2).

Full `pickSleepCandidates` matrix (active/pinned/audible/agent/recent/never-seen/viewless/already-down excluded; aged included; blocklist exact + subdomain in, suffix-spoof and similar-host out; disabled budget; order-filtered output), a real-tree sweep asserting sleep preserves url/title/scrollHint/position and keeps active/pinned/audible/blocklisted tabs alive, wake-at-position with the saved url reloaded and scroll re-scheduled (plus already-awake idempotence and the per-tree `sleepAfterMs` override via `registerTree`), the crash single-auto-restore guard (first crash → auto-restored, budget consumed; second crash and `killed` → stay crashed requiring user action; clean-exit ignored; explicit wake restores), `mapMetricsToTabs` matrix + stub-safe `sampleMetrics` + sampler start/stop, the `performance` settings round-trip (defaults load-through, persistence, DEFAULTS pollution guard, reset-restores), and `spellcheckLanguagesForLocale`/`enableSpellcheck`/`disableSpellcheck`/`hostIsBlocklisted` edges.
